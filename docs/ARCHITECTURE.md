# MindRoot - architecture contract

This file is the contract every module is written against. When code and this file disagree, fix one of them in the same change. Where a module has a wider API than listed, the module's header comment is the detailed reference. Additions are allowed; the signatures listed are the ones other modules may rely on.

## 1. Promises the app keeps

1. **Opens by double-clicking `index.html`.** No build step, no server, no install. Everything works from `file://`.
2. **Works with no network, ever.** No CDN, no remote font, no analytics, no fetch of anything but `blob:`/`data:` URLs. The test runner blocks every other request and turns the suite red. The one exception is the optional AI assistance (`features/ai.js`), which the person opens themselves: it does nothing until a feature is switched on in Settings and a key is given, and then sends only the words of the node and of the nodes round it, to the provider the person chose, when the feature is used. The suites stand a fake provider in its place (`page.route`), so none of them reaches a real one.
3. **Responsive.** From a 320 px phone to a 2560 px desktop, touch or mouse or pen or keyboard. Phones get bottom sheets and a thumb bar, not a squeezed desktop.
4. **Web app.** Served over http(s) it is an installable PWA (manifest + service worker, cache-first) that keeps working offline. On `file://` neither is registered.
5. **Your maps are plain Markdown.** The `.md` dialect is a plain outline, so every map opens unchanged and stays readable in Obsidian, VS Code or any editor.
6. **Nothing is lost.** Automatic saving to IndexedDB, one labelled undo history over every change, a per-project trash, timed copies of maps, ZIP/JSON backup and restore.

## 2. Runtime rules (non-negotiable)

- **Classic scripts only.** No `type="module"`, no `import`, no bundler. Each file is an IIFE that hangs its API on `window.MindRoot` (`ns` inside the file):
  ```js
  /* MindRoot - <what this file is, in one line>.
   *
   * <why it exists / how it works, briefly> */
  window.MindRoot = window.MindRoot || {};
  (function (ns) {
    'use strict';
    function render(tree) { ... }          // named function declarations
    ns.mapview = { render: render, ... };  // exported by reference
  })(window.MindRoot);
  ```
  ES2020 syntax is fine (`const`, `let`, arrow functions, classes, `async/await`, optional chaining). Target the last two versions of Chrome, Edge, Safari, Firefox (Safari 16.4+).
- **Load order** is the order of `<script>` tags in `index.html` (section 5). A module may read other namespaces only at call time, never at load time, except those loaded before it.
- **No fetch/XHR of local files.** Anything a page needs at run time (font bytes for export, templates, sample maps) ships inside a `.js` file. Optional heavy code is lazy-loaded by injecting a classic `<script src>` (works on `file://`).
- **Storage is shared** by every `file://` page in Chromium (other apps included). So: IndexedDB database `mindroot2`, localStorage keys prefixed `mindroot2:`, BroadcastChannel `mindroot2`. Every `localStorage` access is wrapped in try/catch (private modes throw).
- **Query parameters** (tests and support): `?db=<name>` opens another database; a page that names its database seeds no welcome project unless it says `?welcome=1`; `?lang=it|en` picks the language.
- **No `alert`, `confirm`, `prompt`.** Use `ns.ui.dialog` / `ns.ui.confirm` / toasts.
- **No innerHTML with unescaped user text.** Use `ns.util.h()` or `ns.util.escapeHtml`. Markdown inline HTML is rendered through `ns.doc.inlineHtml`, which whitelists.
- **Security of imported data:** reject `..` paths, strip `__MACOSX`, `.DS_Store`, `Thumbs.db`; never execute imported content; SVG drawings are displayed through `<img>` (never inlined into the DOM).
- **Third-party code** lives only in `vendor/` with its licence next to it: `vendor/montserrat-font.js` (OFL, base64 font for exports), `vendor/liquid-glass.iife.js` (MIT, optional decoration). Nothing else. jQuery is not used.

## 4. Shared APIs

Signatures below are the contract. Modules may add more, never change these.

### 4.1 `ns.util` (core/util.js)
```

slugify(name, fallback?) -> string           // Unicode-aware (\p{L}\p{N}), NFD accents stripped, '-' joined, max 60
clamp(v, lo, hi), lerp(a, b, t)
debounce(fn, ms) -> fn (fn.flush(), fn.cancel()), throttleFrame(fn) -> fn (one call per animation frame)
nextFrame() -> Promise                      // rAF with a 50 ms timeout fallback (hidden tabs)
download(blob, filename)                    // a[download] + revoke after 30 s; navigator.share fallback on iOS standalone
pickFiles({accept, multiple, directory}) -> Promise<File[]>   // resolves [] on cancel
readAsText(file) / readAsArrayBuffer(file) / readAsDataURL(blob) -> Promise

isMac, isTouch (coarse pointer), isStandalone, isFileProtocol, reducedMotion() -> bool (live)

### 4.2 `ns.i18n` (core/i18n.js)
```
init(lang?)                  // 'en' | 'it'; default: ?lang=, then prefs (the choice made in Settings), then English. The browser's language is never read.
lang() -> 'en' | 'it'
add({ en: {key: text}, it: {key: text} })   // every module registers its own strings at load time
t(key, vars?) -> string      // '{name}' placeholders; missing key -> English -> the key itself (and a console.warn in tests only)
plural(key, n, vars?) -> string   // keys key.one / key.other, Intl.PluralRules
setLang(lang)                // persists, emits 'lang' on the bus; UI re-renders its text
apply(root)                  // fills [data-i18n], [data-i18n-aria-label] ... under root
keys(lang?) / has(key) / number(n, opts) / list(items, type)
```
A missing key falls back to English, then to the key itself; under an automated browser (`navigator.webdriver`) it also warns once in the console. The journey-tablet suite checks that every key exists in both languages and that the Italian copy has no exclamation mark, em-dash or emoji.
Keys are dotted and owned by the module that uses them (`sidebar.newProject`, `trash.empty`). English is the main language: every string is written in English first, and the Italian dictionary follows it key for key. Copy in both languages: sentence case, no exclamation marks, no emoji, no em-dash; verbs first ("Undo", "Move to trash"). History labels go through `t()` too.

### 4.4 `ns.prefs` (core/prefs.js)
`get(key)`, `set(key, value)`, `on(key, fn)`. One JSON blob in localStorage `mindroot2:prefs` (versioned, deep-merged onto defaults, unknown keys dropped, debounced write, flush on pagehide). Defaults:
```
theme: 'system' | 'light' | 'dark'          ('system')
lang: null                                   (auto)
reduceTransparency: false
liquidGlass: true                            (decorative refraction on Chromium desktop only)
appCursor: true                              (MindRoot's own themed arrow; false: html[data-cursor="system"], the system cursors)
sidebarOpen: true                            (wide screens only)
expanded: {}                                 (projectId -> bool in the sidebar)
branchText: true                             (node text tinted by branch colour)
syncSelection: true                          (map <-> Markdown caret)
notesOpen: false                             (every note open as a card)
diceColors: false                            (random colour for new nodes)
sourceOpen: false, sourceHeight: 0.34        (Markdown panel, fraction of the stage)
copies: { every: 1, unit: 'h' }              (clock copies)
export: { format:'svg', notes:true, expand:true, drawings:false, paper:'light' }
pen: { tool:'pen', color:'#15171c', size:2, eraser:'part' }
viewer: 'split'                              ('split' | 'full' | 'card')
ai: { ..., labels: true, ghost: false, chat: false, chatMap: false, chatScope: 'node', readProjects: {}, chatBoards: 'text' }   (features/ai.js; the key is never here)
```
There is no `direction` any more: the side a branch grows on is written in the map (see 4.8). A key the blob holds but this version does not know is dropped at load; `prefs.legacy(key)` still answers what the blob said for it, and `prefs.forget(key)` writes the blob again without it, at once (the session reads the old `direction` once, see 4.15). A key read with `legacy` (or named with `prefs.keep(key)`) is kept until it is forgotten: every write of this tab carries it as it was read, or as the blob has it now when another tab wrote it later, and another tab writing or dropping it is followed through the `storage` event - so a tab that cannot act on it (read-only) never drops it for the one that can.
```
noteSize: null
```
The theme is also mirrored synchronously to `localStorage['mindroot2:theme']` so the inline `<head>` script applies it before first paint.

Also: `define(key, default, {free})` for a module's own preference (used by editor `recentColors`, ink `ink` and `inkCoach` `{used, shown}`, media `mediaViewer`, settings `backup`, notebook `notebookExport {paper}`), `reset`, `flush`, `defaults`, `all`, `available`. The export format also allows `'png'`.

Tooltips show on hover with a fine pointer, or on keyboard focus right after a key press; never after a touch. The optional liquid-glass decoration is `ns.glass` (in ui.js): lazy-loaded, decorative only.
### 4.6 `ns.float` (core/float.js)
`attach(panel, grip)`, `moved(panel) -> bool`, `anchor(panel)` (forget a manual move), `place(panel, rect)` (clamped). 3 px threshold, pointer capture, clamp to the stage keeping 48 px graspable, double-click grip to put back, reflow on `visualViewport` resize.

`history.undo` / `history.redo` wait for the open notebooks to write what they hold (a pen's strokes become a step a moment after it lifts) before they travel, so Undo right after a stroke takes back that stroke. While the board is shown, keys meant for the hidden map (node.*, navigate.*, format.*, zoom and fit) do nothing but bring the focus back to the board; a node chosen deliberately (a search result) brings the map back.

`Mod` = Ctrl on Windows/Linux, Cmd on Mac. Matching uses `event.key` with an `event.code` fallback. Keys are not dispatched while focus is in a text field, unless the binding says `{global:true}`: Mod+K (`palette.open`), Mod+S (`file.save`), Mod+M (`source.toggle`), F1 (`help.open`). With the focus on the page itself the map's keys act on the map, except while a panel over it (a note, the colour picker, a node being written) is open. Escape is handled before any binding, by `ui.escape` (the top open layer closes), wherever the focus is. Dialogs and the palette stand the dispatcher down. The palette, the help sheet, button tooltips and the thumb-bar "more" sheet are all generated from this registry, so they never drift.

### 4.8 `ns.doc` (model/doc.js) - the Markdown model

**Nodes anywhere, still attached.** Any node but the map's one root may carry `<!-- at: x,y -->` (written after `side`, before `color`): the middle of its box from the middle of its parent's (a top node of a map with several: on the map). The layout takes such a node out of its siblings' stack, hangs it there with its branch, and grows its children on the side it stands on; top trees with a place stand there, the others keep their column under the lowest of them. **From the circle.** A branch of a root put by hand over or under the root's line (its box overlapping the line's span) leaves from the root's circle, the middle of the line, and comes down onto its own line right under the circle (`layout.links`, `mapview.linkEnds`, the drop preview's dashed link); one put beyond the line's end leaves from the end, and the ones in the stack as ever. **A node let go on others.** `editor.placeFree` asks the layout (`view.layoutOf(tree)`: the layout a tree would have with the sizes drawn now, not drawn) for what the edit would give, so a node that leaves its siblings' stack lands where it was let go even though its parent re-centres on those that stay, then looks for boxes of other nodes that the node's whole branch touches (a gap of 10 kept) and acts on the pref `dropOverlap`: `'move'` (default) puts the branch at the free place nearest to where it was let go (rings of 12 px, 900 px of reach, 80 ms), `'aside'` keeps it there and puts each branch it covers at the free place nearest to where it stood (a covered ancestor cannot step aside: the node moves instead), `'keep'` leaves them overlapping. Then the whole predicted layout is looked at (`fixAll`): whatever touches and did not before - the edit moves what it does not touch (a parent re-centres on the children that stay, and every node put by hand under it moves with it) - is put right by moving the branch put by hand, never one the layout placed, to its nearest free place (up to four rounds); an overlap the person already had ("keep") is left alone. `ns.editor.placeFree(path, x, y)` is exported for tests and hosts. A random-drop test (800 drops, both modes) leaves nothing touching; 841 nodes cost 20-70 ms a drop. One edit, one undo step (`editor.label.place`). Settings, Map, has the choice. **Lists in the words under a title.** In a quoted text (body or note), a line after the first that is a list item keeps its indent (`sanitizeNote`, and reading); the body's view draws such lines as `span.md-list > span.md-li.md-li--<depth>` with `.md-li-dot`, `.md-li-num` or a `span.md-check[role=checkbox][data-i]`, every word through the inline renderer. Words with no list are drawn exactly as before.
**Sides.** A tree root is a node with no node above it (the map's one root, or each top node of a map with several); its children are the first-level branches. A first-level branch that grows on the left carries the end-of-line marker `<!-- side: left -->`; no marker is the right. Everything under a branch grows on its side, whatever marker its own line carries (a marker below the first level is not read). The marker is peeled like the others, in any order and spacing, and written back in the canonical order title, role, image, draw, fold, side, colour (colour last). The value is read as a word (`[a-z][a-z-]*`): only `left` means something today, any other word (a later `up` or `down`) is read as the right and written back unchanged, so a file from a later version is not damaged by an edit here. `addSibling` beside a first-level branch copies its side; `rename`, `setColor`, `move` and every other edit keep the marker with its line. A title typed to look like the marker is escaped (`\<!--`) like any other.

### 4.15 `ns.session` (map/session.js) - the open map
```

The session follows the store: whatever `store.here()` names is what is shown, so the sidebar, palette, undo and imports simply change the store (or call `open`). It hears the bus `store` event through a listener added when session.js loads, ahead of every feature module. An open map deleted with nobody saying where to go gives way to its neighbour. Folds are kept per map as lineage keys in `store.setMapView` so they survive edits and reloads; a list starting with `BY_HAND` (`'\u0000'`) means "folded by hand" and wins over the file's fold markers.

Earlier versions had a setting, "grows on both sides", that balanced the branches by itself (a per-map `direction` in the map view, and a global preference for maps that had none). At init the session reads the old preference once (`prefs.legacy('direction')`): if it said 'both', every map with no direction of its own is marked 'both', and the preference is forgotten (`prefs.forget`). Only a tab that saves the data does this: a read-only tab (another tab holds the data, perhaps an older version's) would mark the maps in its memory alone and still drop the preference, and the next tab would open them all on the right; so it leaves the preference where it is (`prefs.legacy` holds a key it has read in the blob, whatever else the tab writes, until it is forgotten, and lets it go when another tab writes the blob without it), shows those maps the balanced way meanwhile, and does the marking when it may write (`syncReadOnly`). A map marked 'both' opens with the legacy balanced layout; once a render has drawn its first-level branches (and the tab may write), the side each landed on is written as markers with `doc.setSides`, ONE undo step labelled `session.label.keepSides` ("keep the branch sides"), then the layout switches to the markers and the map's direction is cleared. The two layouts draw the same map, so nothing moves; Undo takes the markers back (the map then grows to the right). Clock copies taken before the sides were written carry no markers either: once the map is migrated, their preview shows every branch on the right and restoring one gives a map that grows to the right (the copies follow the open map's layout, not the one it had when they were taken; writing sides into a restored copy would be a change nobody asked for, and its branches can be moved to the left by hand). An undo step was chosen over a silent write because every change of a map's text in MindRoot is a labelled step, and the toast says what happened. A tab that cannot write keeps the balanced layout until it can.

### 4.16 Feature modules
Each exposes `init()` (called once by `app.js` after the store is ready, in the order `tabs, sidebar, session, editor, notes, colorpicker, source, exporter, media, ink, notebook, trash, copies, palette, settings, help, welcome, pwa`; a missing module or a failing init leaves its feature out with a banner, never the app) and registers its commands with `ns.commands` and its strings with `ns.i18n`. A node added and named is one undo step; Escape on it takes the add back. In the title Enter saves; in the words under it Enter breaks the line and goes on with a list (an empty item ends it), Tab / Shift+Tab nest a list item, Mod+Enter saves from either; the format bar has bulleted, numbered and task list buttons. A new name written on the map's primary node (`doc.primaryPath`) renames the map in the same step, and `sidebar.renameMap` writes the map's new name on that node, one step (a node with no words of its own is left alone). The selected node shows a move grip (drawn by mapview, 'grip' event when tapped) that lifts it at once, mouse or finger, and two thread handles ('wire' event when tapped): `in` on the thread that holds it to its parent, `out` under the grip. Pulled, a thread follows the pointer (`view.threadGhost(path, 'in'|'out', at)`, an edge auto-pan shared with the node drag through `edgePanner`): `in` let go on a node plugs the branch into it as its last child (`moveBranch(..., 'child')`, label "attach the branch"), in the open detaches it where it stands (`detach`), over its own parent does nothing, into its own branch is refused; `out` let go on a node takes that node in as a child of the pulled one. The test runner waits for `booted === true`; code inside the page can await `ready`. If boot itself fails, a failure screen offers the raw stored data as a JSON download.

## 6. Design system (css/tokens.css)

Calm, content-first, Apple-adjacent. Colour is spent on branches; the chrome is neutral grey plus one green accent.

- Tokens: `--paper --paper-raised --paper-sunken --ink --ink-soft --ink-faint --ink-disabled --line --line-strong --line-control --accent --on-accent --accent-soft --danger --on-danger --danger-soft --focus --scrim --note` + glass tokens + `--shadow-sm/md/lift`. Dark values defined twice: `@media (prefers-color-scheme: dark) { :root:not([data-theme=light]) {...} }` and `:root[data-theme=dark] {...}`. Contrast: AA for text, 3:1 for controls, both themes.
- Type: chrome `system-ui` stack; map, brand and exports Montserrat. Scale `--fs-xs 12 / sm 13 / md 15 / lg 18 / xl 24 / 2xl 32`. Inputs ≥ 16 px on coarse pointers.
- Space: 4 px grid `--sp-1..7`. Radii: capsule (floating bars), 8 (controls), 12 (menus/popovers), 16 (panels/dialogs/sheets), 6 (chips/kbd).
- z-index only from the scale: `--z-map 0, --z-map-overlay 10, --z-chrome 20, --z-panel 30, --z-popover 40, --z-sheet 50, --z-scrim 55, --z-dialog 60, --z-toast 70, --z-tooltip 80, --z-drag 90`.
- Breakpoints: compact < 640, medium 640-1023, expanded ≥ 1024; `(max-height: 480px)` landscape phones (menus become sheets; targets stay 44 px). Target size from `(pointer: coarse)` (44 px) not width; hover only inside `@media (hover: hover) and (pointer: fine)`.
- Cursors: the map is `grab` on its empty background (set once on `.mv`, never toggled), `grabbing` while it pans (the shield) and while a node is dragged (`html[data-node-drag]`), MindRoot's own arrow on nodes, the I-beam in text fields. MindRoot's arrow is the app-wide default: the select tool's navigation arrow (`M5.5 3.5l12.5 7-5.8 1.6-2.7 5.9z`, 24-unit box drawn at 32 px from viewBox `1 0.5 24 24` so the tip is the hotspot `6 4`; one vector picture the browser draws at the screen's density, not `image-set()`, which crashed Chromium's renderer with SVG pictures), dark ink ringed with white on the light theme, light ink ringed with near-black on the dark one (`--cursor-arrow-light` / `--cursor-arrow-dark` in tokens.css). `--mr-cursor` holds the one in use, only under `(any-hover: hover) and (any-pointer: fine) and (forced-colors: none)` and while `appCursor` is on; `body` and every rule that would say `pointer` or `default` read `var(--mr-cursor, pointer|default)`, so without it they fall back to the system's cursors. Links keep the hand; text fields and contenteditable keep the I-beam. The drawing editor shows the tool: the pen is its nib, the hollow outline of the mark it will leave (as wide as its line on screen, never under 6 px; the highlighter a chisel outline) with only a faint tint of its colour inside, the outline the sheet's own ink softened (dark on light paper, light on dark) with a hair of the sheet's colour outside. The page draws it (`div.ink__pen-ring`, placed with a transform on every mouse or pen move over the sheet, hidden while a stroke is drawn, never for a finger) and the system cursor is `none` while it is live, because a browser may drop a cursor image and show the crosshair instead, above all under a hovering stylus; no media query decides it, and forced colours get the system cursors; text the I-beam, shapes the crosshair, select MindRoot's arrow and move / resize over the selection, hand grab / grabbing, the eraser its own circle.
- Component tokens may be declared by the component's own stylesheet in a `:root` block when only it uses them (`--ed-*`, `--cp-*`, `--note-*` in editor.css), each with its reason.
- Motion (css/motion.css is the only place durations and curves live; component stylesheets - editor, source, media, ink - carry their own transitions using only these tokens, with their own reduced-motion block): `--dur-press 100ms, --dur-hover 120ms, --dur-pop 160ms, --dur-panel 220ms, --dur-overlay 260ms, --dur-toast 320ms, --dur-sheet 420ms, --dur-map 220ms`; `--ease-out cubic-bezier(.23,1,.32,1)`, `--ease-in-out cubic-bezier(.77,0,.175,1)`, `--ease-drawer cubic-bezier(.32,.72,0,1)`. No `transition: all`, no ease-in, no `scale(0)`, no keyframes for retriggerable UI, no animation on keyboard paths (palette, shortcuts, arrow navigation). `[hidden]` panels animate with `@starting-style` + `transition-behavior: allow-discrete`; reduced motion = opacity-only crossfades and instant map/camera, durations 1 ms (not 0).
- Visual language "Liquid" (v2): `css/liquid.css`, loaded after the component sheets and before motion.css, repaints the surfaces and never their geometry (sizes, gaps, targets stay the component sheets'). A liquid surface is a blurred, saturated, slightly brightened backdrop, a clear tint (`--g-tint`), a sheen (`::before`, `--glass-sheen`), a specular rim (`::after`, a 1px `--glass-edge` gradient border cut out with a mask) and an inner glow plus a long shadow (`--glass-glow`, `--glass-shadow`); the page under it is lit by `--ambient` on `#app` (the body keeps the exact paper colour). Menus, popovers, dialogs, sheets, panels, the palette, the sidebar, note bubbles, toasts and tooltips are frosted surfaces of the same family; primary and pressed buttons are lit accent glass and give 0.97 under the finger. Every fallback below applies to all of them.
- Layout v3 (the dock): the sidebar is a floating glass panel - inside its column on expanded screens (a margin of --chrome-gap all round but the map side, so the map's box is unchanged), an inset drawer with all corners rounded from 640 to 1023px. Menus opened from the dock open upwards; `ui.position` measures a menu again whenever the cap it sets changes its height (it was first measured under the 70vh fallback), so an upward menu keeps its foot by its anchor.
- Materials: glass (`.glass`, `.glass--thin`, `.glass--thick`) only on the floating functional layer (top capsules, thumb bar, node toolbar, format bar, menus); never on content, never glass on glass, at most 4 visible. Solid fallbacks for no backdrop-filter, `prefers-reduced-transparency`, the manual "Reduce transparency" setting, `prefers-contrast: more`, `forced-colors`. The liquid-glass library is optional decoration only: lazy-loaded, Chromium + fine pointer + motion allowed + setting on, on the welcome card and the top capsules at most, never with pointer-tracking elasticity.
- Icons: one inline `<symbol>` sprite in index.html (24-unit stroke icons, 1.7 stroke, round caps), used via `ns.ui.icon(name)`.

## 7. Tests

- `node test/run.js` runs every suite headless in Chromium via Playwright (`--headed` uses xvfb-run on Linux). Every suite gets a fresh browser context (empty storage), network requests fail the suite, and so do page errors and console errors.
- Unit suites: `test/unit/<name>.html` loads exactly the scripts it needs, `../harness.js` and `<name>.test.js`, then `T.run()`. Fast, no layout waits.
- E2E suites: `test/e2e/<name>.e2e.js` exports `async function (t)` and drives the real `index.html` (see the header of `test/run.js`). Wait for conditions, never fixed sleeps longer than an animation.

## 8. Code style

- Comments say why, not what, in plain English; a header comment per file. Match the surrounding density.
- Small named functions; no classes required; no frameworks.
- All user-facing text through `ns.i18n.t`. All sizes, colours, durations through CSS tokens.
- Accessibility: real `<button>`s, `aria-label` on icon buttons, roving tabindex in trees and lists, `aria-live` for save state and toasts, focus returns to the trigger when a layer closes, visible `:focus-visible`.
- Never block input on an animation. Never read layout inside `pointermove` without batching to a frame.
